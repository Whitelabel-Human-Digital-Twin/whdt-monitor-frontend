## Project overview

Frontend for a WHDT (Human Digital Twin) research platform. The app monitors Human Digital Twins (HDTs) — each HDT has property events streamed from wearable/sensor data, organized into models. Two separate Ktor (Kotlin) backends serve the frontend:

- **Creation service** (`localhost:8080`) — creates HDTs, handles Excel bulk upload
- **Persistence service** (`localhost:8081`) — stores and queries HDT events, models, property history

## Commands

```bash
npm run dev       # Start dev server with Turbopack at localhost:3000
npm run build     # Production build
npm run lint      # ESLint
npm run gen:api   # Regenerate TypeScript types from the persistence backend's OpenAPI schema
                  # Requires the persistence service running at localhost:8081
```

There are no tests.

## Architecture

### API layer

`src/lib/api/client.ts` exports a typed `openapi-fetch` client bound to `localhost:8081`. All persistence queries go through this client using the generated types from `src/lib/api/schema.d.ts`.

**Do not edit `src/lib/api/schema.d.ts` manually** — it is auto-generated by `npm run gen:api` from `http://localhost:8081/openapi.yaml`.

HDT creation and Excel upload bypass the typed client and use raw `fetch` against the Next.js rewrite proxy (`/api/creation/...`). The `next.config.ts` rewrites handle routing:
- `/api/creation/:path*` → `localhost:8080`
- `/api/persistence/:path*` → `localhost:8081`

### Pages and routing

| Route | Purpose |
|---|---|
| `/` | HDT list + Excel upload (`HdtManager`) |
| `/query-builder` | Aggregate stats (avg/min/max) and comparison search across HDTs |
| `/hdt/[id]/property-live` | Live line chart for a selected property of a specific HDT |

### Component patterns

All components use `"use client"`. There are no server components beyond the root layout.

`HdtDetail` polls `/hdts/{id}/snapshot` every 5 seconds for live property updates. The property-live page fetches history on demand via `POST /query/event/values/history`.

`src/app/query-builder/types/query.ts` defines the local `FilterOperator` type and maps it to the backend's `PropertyComparisonDto` comparison enum (GT, LT, EQ, GTE, LTE).

The persistence spec (v0.2.0+) uses `tags` (not `metadata`) on `HumanDigitalTwinDocument`, `ModelDocument`, `PropertyDocument`, `PropertySpecEntry`, `ModelSpecEntry`, and `HdtSpecResponse`. `PropertyObservation.metadata` is unchanged.
